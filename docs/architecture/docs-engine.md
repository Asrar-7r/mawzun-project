# محرك التوثيق

مركز التوثيق على المسار `/docs` يعرض نفس ملفات `docs/` في المستودع: ملف Markdown واحد
يساوي صفحة واحدة، والمجلد يساوي قسماً في الشريط الجانبي. لا قاعدة بيانات ولا CMS —
المستودع هو مصدر الحقيقة، والتطبيق يقرأه وقت البناء فقط.

## المكوّنات

| الجزء | الموقع | المسؤولية |
| --- | --- | --- |
| ملفات المصدر | `docs/` | المحتوى المرجعي (يُقرأ على GitHub وداخل التطبيق معاً) |
| محلّل الترويسة | `src/lib/docs/frontmatter.ts` | استخراج `title` و`description` و`order` من كتلة `---` |
| الفهرس | `src/lib/docs/registry.ts` | بناء شجرة الأقسام، البحث المسطّح، السابق/التالي، وسائط البناء الساكن |
| العرض | `src/components/docs/DocsMarkdown.tsx` | تحويل Markdown إلى مكوّنات تطابق نظام التصميم |
| المسارات | `src/app/docs/` | صفحة الهبوط، مسار `[...slug]`، وصفحة `not-found` |

## إضافة صفحة جديدة

1. أنشئ ملف `docs/<section>/<slug>.md` داخل قسم موجود (`getting-started`, `architecture`,
   `workflow`, `reference`, `adr`). الأقسام معرّفة في مصفوفة `SECTIONS` داخل
   [`registry.ts`](https://github.com/Asrar-7r/mawzun-project/blob/main/src/lib/docs/registry.ts) —
   أي مجلد غير مذكور هناك يُتجاهل.
2. ابدأ الملف بترويسة أمامية تحدد الترتيب والبيانات الوصفية:

```md
---
title: عنوان الصفحة
description: جملة واحدة تظهر تحت العنوان وفي نتائج البحث.
order: 3
---

# عنوان الصفحة

المحتوى...
```

3. افتح الصفحة الأولى بعنوان `#` واحد — يُزال تلقائياً من الجسم لأن المسار يعرض
   عنوان الترويسة في ترويسة خاصة (انظر `stripLeadingH1`).
4. اربط الصفحات بمسارات مطلقة (`/docs/architecture/overview`) لا نسبية، لتستمر الروابط
   صالحة على GitHub وداخل التطبيق معاً. الروابط الداخلية تُعرض عبر `next/link`
   فتبقى التنقّل لحظياً بلا إعادة تحميل.
5. تحقّق قبل الدفع:

```bash
bun run docs:check   # ترويسات + ترتيب + روابط داخلية
bun run lint         # فحص الكود
bun run build        # توليد كل الصفحات ساكنًا
```

## قواعد الترويسة والترتيب

- `title` و`description` و`order` إلزامية في كل ملف عدا `docs/README.md` (صفحة الهبوط).
- `order` يحدّد الترتيب داخل القسم؛ عند التساوي يُرتَّب أبجدياً بالعربية.
- لا تُكرّر نفس `order` مرتين داخل القسم الواحد — يلتقطها `docs:check`.

## كيف يُبنى العرض؟

- `getDocsNav()` تقرأ كل قسم وملفاته `.md` وترتّبها — تُغذّي الشريط الجانبي
  (`DocsSidebar`) وبطاقات الهبوط.
- `getDoc(slug)` تُعيد بيانات الصفحة وجسمها الخام لمسار `[...slug]`.
- `generateStaticParams()` تولّد مساراً لكل ملف، و`dynamicParams = false` يجعل أي slug
  مجهول يسقط على صفحة `not-found` المخصّصة.
- `DocsMarkdown` يرسم الجداول (GFM)، ويثبّت معرّفات للعناوين (`rehype-slug`) لتعمل
  روابط المقاطع (`#...`)، ويعرض الروابط الخارجية في تبويب جديد.
- `DocsPager` يبني السابق/التالي من ترتيب القراءة المسطّح عبر الأقسام.
- `DocsToc` (فهرس «في هذه الصفحة») يجمع عناوين `h2`/`h3` من الصفحة المعروضة نفسها،
  فلا يعتمد على تخمين المعرّفات.

## البحث والتنقّل

- حقل البحث في `DocsSidebar` يرشّح فورياً حسب العنوان والوصف والمسار.
- مسار التنقّل (`DocsBreadcrumb`) يعرض: التوثيق › القسم › الصفحة.
- الشريط العلوي (`TopBar`) يكتشف مسارات `/docs` ويعرض «مركز التوثيق» بدل مرحلة التدقيق.

راجع [المكوّنات](/docs/architecture/components) لواجهات مكوّنات التوثيق، و
[الاصطلاحات البرمجية](/docs/reference/conventions) لقواعد الفروع والوسوم قبل المساهمة.
